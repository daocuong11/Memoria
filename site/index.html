The problem

Every switch starts with a re-explain.

Claude doesn't remember yesterday's session. Codex doesn't know the decision you made in Gemini CLI. When you hit a limit mid-task, you spend the next ten minutes rebuilding context.

Without Memoria

14:30, limit reached

You open another tool at 14:31 and paste in the same background, the same decisions and the same half-finished plan.

With Memoria

14:31, already caught up

The new tool opens with your open tasks, locked decisions, current branch and dirty files. You keep going.

How it works

Capture, extract, recall.

Memoria runs in your tray and watches the session files your tools already write. There is nothing to wire up per project.

  1. Capture

    Sessions from nine AI coding tools are read as they happen. When a tool reports a usage limit, Memoria snapshots your files, commands and git state right away.

  2. Extract

    Sessions become structured memories: the agent’s todos with their real status, your answers to its questions, build errors and the edits that fixed them, and commits. No model needed. Free-form sentences stay drafts you can search; add Ollama for clean sentence extraction.

  3. Recall

    Any MCP client can recall and curate memories. A resume block is also written into AGENTS.md, CLAUDE.md and GEMINI.md for tools that read files.

A resume block that stays current

About four minutes after a session goes quiet, or immediately on a usage limit, Memoria writes an idempotent block into your project's context files.

Newer decisions replace older ones about the same subject, so the block does not fill up with stale choices.

## SESSION RESUME> claude · 14:32 · branch: feat/authOpen tasks:- [ ] finish the refresh-token endpoint in routes/api.tsLocked decisions (do not repeat):- JWT access tokens, 15 min, not sessionsDirty files (git): src/auth/middleware.ts, src/auth/routes.ts_Continue the work above. Do not re-litigate locked decisions._

Privacy

Your sessions stay on your machine.

No account, no cloud service and no telemetry. Everything lives in a local SQLite database.

Local by default

  • Capture, extraction and search run on your computer, in ~/.memoria.
  • Works with no model at all for structured capture and resume. Ollama is the upgrade for clean sentence extraction.
  • Nothing leaves your machine unless you opt in: an OpenAI-compatible endpoint, webhook notifications, or encrypted sync.
  • API keys, tokens, private keys and passwords are redacted before anything is stored.

Optional encrypted sync

  • Move your library between your own devices with end-to-end encrypted .memsync bundles (AES-256-GCM).
  • Use a manual export or a shared folder such as Dropbox, iCloud or Syncthing. No server involved.

Never synced: embeddings, secrets, settings, raw transcripts and machine-local paths.

$ npx @xinzzu/memoria@latest server

Dashboard, API and MCP all run on http://127.0.0.1:48210. Prefer a global install? npm install -g @xinzzu/memoria, then memoria server.
